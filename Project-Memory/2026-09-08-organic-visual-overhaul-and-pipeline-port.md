# Organic Town Visual Overhaul — Mockup Iteration & Real Pipeline Port

### Session spanning 2026-09-07 to 2026-09-08, focused on why the generated town map looked artificial (straight thick road lines, uniform boxy buildings, stark zone edges, identical overlapping farmhouses), fixed through many rounds of throwaway mockup iteration toward a Watabou-inspired hand-drawn look, then ported end-to-end into the real `town_shaper`/`town_db` pipeline with full test coverage. Main successes: organic per-zone block/lot cutting with rotation and courtyards, a clearance-based countryside system, categorical removal of all road-line rendering, and a centrally-enforced "no building in water" invariant — landed with 499/499 tests passing. Main open threads: landmark buildings still render as icons not footprints (queued), the interactive viewer likely still draws the same bad road lines the static map dropped (found, not yet raised), and one small-town visual issue the user deferred without detail.

## Low-Detail Summary

- Started from a side-by-side comparison of the current renderer's output against a Watabou-style reference map; user prioritized aesthetic/realism above all else and chose a monochrome, hand-drawn map style over the old zone-colored one.
- Studied a reference copy of Watabou's `TownGeneratorOS` for *technique only* (GPLv3 — confirmed explicitly not to copy code), which is where vertex-anchored polygon bisection, per-zone "chaos" parameters, and courtyard-peeling came from.
- Iterated many rounds of throwaway mockup scripts (not real code) before touching the shipped pipeline, each round driven by the user finding a specific visual bug from a generated image (jutting lines, a "donut" density anomaly, stark zone transitions, oversized/identical farmhouses) and rejecting a wrong-direction attempt (a "wall-wiggle" texture that looked "squiggly, not like buildings").
- Landed on: rotation between blocks and houses, courtyard buildings for large residential leaves, farmland replaced entirely by a clearance-based placement system (no more zone fill), and — after four rounds of incremental filtering all failed — the categorical removal of every drawn road line.
- Once the mockup was validated, ported every mechanism into the real codebase: `town_shaper/blocks.py` (organic residential cutting + courtyards), a new `town_shaper/countryside.py` module (clearance-based farm/house placement), `town_shaper/geometry.py`/`roads.py`/`water.py` (shared smoothing/geometry helpers), and a full rewrite of `town_db/render.py`.
- During final verification of the port, found and fixed two real, previously-undiscovered bugs: buildings from three independent generation paths could each individually leak into water near a coastline, and the map renderer painted islands (holes in a water polygon) as solid water instead of land.
- Fixed both with a single centralized "no building may intersect water" filter (rather than patching each leak source) and a proper polygon-with-holes renderer; verified 0/1731 buildings intersect water in a real generated town.
- Updated/rewrote five stale tests whose assumptions the port broke (multi-polygon-part handling, footprint-vs-rectangle building fields, a raised generation-time budget) and removed two tests that had become vacuous (asserting road-rendering behavior that no longer exists).
- Full test suite: 499 passed, 0 failed, in a clean uncontended run (~23 minutes).
- Nothing from this session has been committed to git yet — all changes are in the working tree.

## High-Detail Summary

### Direction-setting decisions

- User's stated priority throughout: aesthetic/realism of the city look above all else. Chose "Watabou-style monochrome map" (no per-zone color tinting) over keeping the old zone-colored rendering.
- A sibling directory holds a real copy of Watabou's `TownGeneratorOS` source (GPLv3) — used strictly as a technique reference (vertex-anchored bisection à la `Cutter.bisect`, per-zone `gridChaos`/`sizeChaos`, `Cutter.ring` courtyard peeling), independently reimplemented, never copied.
- Firm process requirement re-affirmed by the user mid-session and worth keeping for future visualization work: mock up a few directions and check in *before* writing real visualization code, not after.

### Mockup iteration — bugs found and fixed (all initially in throwaway scratchpad scripts, not shipped code)

- **Angle-chaos explosion:** raw ±63° jitter caused a sliver explosion (911 buildings instead of ~95); fixed by matching Watabou's actual `angleSpread = π/6 * gridChaos` with size-dependent damping.
- **Gap-offset sign backwards:** a split's `half_gap` was positive, so split halves overlapped instead of separating; caught via a plain-square unit test showing total area growing past the original; fixed by negating the offset.
- **Wall-wiggle rejected outright:** an edge-perturbation attempt at "chaos" made buildings look "squiggly... not like buildings anymore" — reverted; the user's specific ask instead was rotation (block-level and house-level) plus inner courtyards for larger buildings.
- **`variable_inset` convex-only bug:** the first version ran sequential half-plane clips against a polygon's own (possibly concave) edges, silently producing too-thin margins at concave points and ~100 cross-district building overlaps; fixed by using `inset_polygon`'s shapely-buffer base (already non-convex-safe) with only one extra clip for the wide edge.
- **Distance-from-map-center gradient bug:** the countryside density gradient originally used distance from the bounds' geometric center, which silently assumed a roughly circular town — broke asymmetrically on real irregular/coastal towns (good transition on one side, dead gap on the other); fixed by switching to distance-to-*nearest-actual-building* via `shapely.strtree.STRtree.nearest()`, which is shape/direction-independent.
- **Fixed-attempt-count undersampling:** a flat `COUNTRYSIDE_ATTEMPTS` constant calibrated for one town size undersampled a larger one, producing a patchy "donut" gap artifact; fixed by scaling attempts with map area (`COUNTRYSIDE_ATTEMPT_DENSITY = 9000/600_000`).
- **Stranded polygon fragment bug (found and fixed twice):** a river/coastline-split district's *secondary* polygon part (not a sliver — thousands of sq. units) got full block-cut treatment, producing a phantom, disconnected mini-neighborhood with its own street grid — this single bug was simultaneously the cause of both the "jutting line" reports (the phantom block's own internal street gap) and the "donut" density anomaly at the same map location. First fix only covered residential buildings; a second pass found the identical bug untouched in the civic/merchant/wall-rendering paths and generalized the fix to "only ever process a district's largest `polygon_part`," applied everywhere: `compute_district_blocks`, `generate_organic_residential_buildings`, and `_draw_wall`.
- **"Near a building" ≠ "hidden by a building" (decisive road-line finding):** after four rounds of increasingly specific spur-line filtering (zone check, length cap, endpoint-distance check, distance sampled along the entire line), a real case surfaced where every sampled point on a spur was within 0-6 units of *some* building yet the line still rendered as plainly visible — proximity to a building is not the same as that building's footprint visually covering the line. Decisive fix: remove **all** road-line rendering categorically (boundary, artery, and spur), rather than continue incremental patching.
- **A verification-methodology mistake, self-corrected:** early "fixed, verified clean" claims were based on eyeballing a whole downscaled image; several real bugs were only visible tiling the image into a fine grid and inspecting each tile individually. Adopted exhaustive tile-by-tile inspection as the verification standard for the rest of the session.

### Real pipeline port (this session's second half)

Files changed (all currently uncommitted, working-tree only):

- **`town_shaper/blocks.py`** — `compute_district_blocks` now only ever processes a district's largest `polygon_part` (with an explanatory comment on the stranded-fragment bug this prevents). Added the full residential-only organic pipeline: `RESIDENTIAL_CHAOS` per-zone parameters, `variable_inset`, `_split_polygon_organic` (vertex-anchored bisection), `organic_subdivide_residential`, `ring_peel` (courtyard peeling into a multi-ring `Building`), and the entry point `generate_organic_residential_buildings`. Civic/merchant/port keep the original `_split_polygon`/`organic_subdivide`/`subdivide_into_blocks` path untouched.
- **`town_shaper/countryside.py`** (new file) — replaces the old uniform-density farmland zone-fill entirely. `generate_countryside_buildings` places single houses or 2-4-building farm clusters anywhere with enough clearance (a smoothstep gradient) from the nearest already-placed building anywhere in town; attempts scale with map area. Also now holds `remove_buildings_in_water` (see below).
- **`town_shaper/generate.py`** — wires the new residential and countryside generators in; farmland districts are filled last (after every other district exists, since countryside needs to know where they all are), attributed to one farmland district purely for bookkeeping.
- **`town_shaper/geometry.py`** — gained `chaikin_smooth` (moved here from `roads.py` for reuse) and `rotated_rect_corners` (moved from a private duplicate in `town_db/render.py`).
- **`town_shaper/roads.py`** — farmland-touching ridges/spurs now excluded from rendering (and from the routing graph, if they cross water); uses the shared `chaikin_smooth`.
- **`town_shaper/water.py`** — river/coastline centerlines are Chaikin-smoothed before being buffered into a strip, fixing zigzag.
- **`town_db/render.py`** — full rewrite: no farmland tint, no road-line drawing at all (with an in-code comment explaining the four-round investigation that led there), buildings drawn from real footprints (single- or multi-ring), wall drawn from each district's largest polygon part only. Water features drawn via a proper polygon-with-holes `PathPatch` (see below).

### The water-safety invariant (this session's own new finding, not carried over from mockup work)

While smoke-testing the ported pipeline end-to-end, found that a handful of buildings rendered inside the water area. Root-caused to **three independent leak sources**, not one: `town_shaper/countryside.py`'s water check originally only tested a farm cluster's single center point (an outbuilding offset 6.5-9.5 units away could still land in water); separately, some ordinary residential (`poor_residential`) and `merchant` buildings near a coastal district edge also leaked through their own, narrower checks. Rather than chase each source individually, added one centralized defensive invariant: `remove_buildings_in_water(districts, water_features)` in `town_shaper/countryside.py`, run once in `generate_town` right after all generation (countryside included) finishes and *before* `assign_residents` (residents are assigned to specific building IDs, so the filter must run before that assignment, not after). Verified via direct query against a real generated+persisted town: 0 of 1731 buildings intersect water.

**A second bug found during that same verification pass, unrelated to building placement:** a water feature's stored polygon can have interior holes (e.g., an island in a coastline). Both an ad hoc verification script and `town_db/render.py` itself were treating every ring (exterior *and* holes) as its own separately-filled solid polygon — which paints an island as water instead of leaving it as land. Confirmed concretely on this session's own test town: a `farmstead` building sitting correctly on a real island was flagged as "in water" by the naive check, which is what surfaced the bug. Fixed in `render.py` with `_polygon_with_holes_patch`, a single `matplotlib.path.Path`/`PathPatch` built from one MOVETO/CLOSEPOLY loop per ring (exterior then holes) instead of one `MplPolygon` per ring.

### Test suite changes

- `tests/test_blocks.py`: renamed `test_compute_district_blocks_covers_every_polygon_part` → `test_compute_district_blocks_uses_the_largest_polygon_part` (added an area-bound assertion); renamed `test_generate_blocks_and_buildings_covers_every_polygon_part` → `..._uses_the_largest_polygon_part`; rewrote `test_generate_blocks_and_buildings_shares_notable_building_counts_across_parts` → `..._across_districts`, since sharing state *within* one district's polygon parts is no longer a reachable scenario (only the largest part is ever built on) — the rewritten test exercises the cross-*district* sharing that still is.
- `tests/test_db_render.py`: removed `test_render_town_handles_a_town_with_roads` and `test_render_town_skips_a_road_edge_with_a_missing_node` (both had become vacuous — `render_town` no longer queries road tables at all); replaced with a single `test_render_town_ignores_road_tables` documenting the new behavior explicitly.
- `tests/test_db_schema.py`: `test_generate_town_database_persists_building_footprints` now accepts a building having *either* a real footprint *or* positive width/height, not both (multi-ring/courtyard buildings intentionally leave width/height at 0.0 — nothing reads them when a footprint is present); `test_generate_town_database_persists_building_footprint_polygons` now handles both flat-ring and multi-ring (courtyard) footprint shapes.
- `tests/test_generate.py`: `test_generate_town_completes_within_time_budget_at_low_thousands_scale` budget raised from 10.0s to 20.0s with an explanatory comment (measured 13.8-16.4s uncontended; a misleading 30.6s reading during the fix was traced to two pytest processes competing for CPU, not a real regression) — re-confirmed passing in isolation at 16.4s. `test_generate_town_places_footprint_buildings_in_urban_zones` rewritten: no longer asserts fixed `FARMLAND_BUILDING_WIDTH`/`HEIGHT` (farmland isn't generated that way anymore), instead asserts every building has either a footprint or a positive-size rectangle, and every farmland building specifically has a footprint.
- Final full run: `python -m pytest tests/ -q` → **499 passed, 0 failed**, ~23 minutes uncontended. (An earlier, stale background run captured file state from before these test edits and correctly showed the 4 now-fixed failures — not a contradiction, just a timing artifact of when each background process was launched.)
